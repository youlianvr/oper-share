## Boundaries

- Reversing binaries/bytecode before exploitation → `reverse-engineering`.
- Defensive code-quality review without an adversary → `dev` router.
- `security-review` (top-level) stays the general code-review pass; this
  router is surface-specific assessment playbooks.

## Rules

- Authorization preamble in each part is not decoration — skipping it is a
  violation, not a shortcut.
- Parts reference each other by path (`security/parts/<name>/`); cross-domain
  links point at `reverse-engineering/parts/<name>/`.
