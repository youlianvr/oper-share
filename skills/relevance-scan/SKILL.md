# relevance-scan — check the workspace before doing the work

> The failure this skill exists for: an agent "boiling inside the
> environment" assumes what is on disk matches its memory of it, and
> builds a second copy of something the workspace already solved. The
> counter-habit is cheap and mechanical: **before creating, check.**

## When this fires (mandatory)

- Any non-trivial task starts: plan, implementation, research brief,
  document, incident.
- Any act of creation: new file, skill, script, doc, cron job.
- The user asks "что уже есть по X" or references past work.

Not needed for: single-line answers, questions whose answer is in the
current conversation, trivial edits inside a file already open.

## The scan — layers in priority order

Check layers top-down; stop descending when a layer answers the question.
Each layer lists what it holds and how to search it.

| # | Layer | What it holds | How to check |
|---|-------|---------------|--------------|
| 1 | **Constitution** | Hard rules, never-destroy, priority ladder | `AGENTS.md` (always already loaded); `_memory/HARD_RULES.md` (H0–H24) |
| 2 | **Normative docs** | How work must be done in this workspace | `docs/` — Skills, Data-Safety, Version-Control, Working-Base, Code, Infrastructure (MCP registry), Governance, Principles, Autonomy-Charter, KB-RAG |
| 3 | **Session entry** | What to read at start, health checks | `BOOT.md` — the one start file; `_memory/INDEX.md`, `_memory/CORE.md` |
| 4 | **Findings** | ~244 dated investigation results, one topic per file | `knowledge/INDEX.md` first; then `grep`/read in `knowledge/findings/` |
| 5 | **Wiki + lessons** | Tool studies, reference analyses, hard-won lessons | `knowledge/wiki/` (incl. SKILLS-INDEX.md, lessons/, finds/), `knowledge/research/` |
| 6 | **Memory** | Owner facts, dangling tasks, error log, wins | `_memory/USER.md`, `_memory/DANGLING_TASKS.md`, `_memory/ERROR_LOG.md`, `_memory/WINS_LOG.md` |
| 7 | **Skills** | Executable contracts for repeated work | `find-skills` catalog query — never a raw `ls` |
| 8 | **Scripts** | Working automation, validators, checkers | `_scripts/` — `grep` by purpose keyword before writing a new one |
| 9 | **Projects** | Per-project code and archives | `projects/<name>/` — check the specific project tree |
| 10 | **Plans** | The current rebuild plan and recorded decisions | `workspace_rebuild_task_plan.md` — verdicts live here, not in memory |

## How to scan (mechanics)

1. **Name the question first.** One sentence: "does the workspace already
   hold X / a decision about X / a tool for X?"
2. **Grep before read.** Search layer candidates by 2–3 distinctive
   keywords (topic terms, not task phrasing). Full-text search beats
   guessing filenames:
   ```bash
   grep -rli "<keyword>" knowledge/ _memory/ docs/ --include="*.md"
   ```
3. **Read hits, not folders.** Open only files whose name or grep context
   matches. Titles lie less than folder listings, but neither is the
   content.
4. **Dated findings win over memory.** A `knowledge/findings/2026-*.md`
   with evidence outranks a recollection. A decision recorded in the plan
   outranks both.
5. **Report the verdict in one line** before proceeding: what was found
   (paths), what was not, and therefore — reuse, extend, or create new.
   For creation tasks this doubles as the `docs/Skills.md` intake proof
   (no coverage → allowed to create).

## Boundaries

- **Do not scan for trivial work.** The check costs ~2 greps; spending
  them on a one-line edit is waste.
- **Do not substitute scanning for asking.** If the scan finds two
  conflicting decisions, surface the conflict to the owner — do not
  resolve it silently.
- **Search tools first.** `code_search` / `grep` over the workspace beats
  `ls` archaeology. The semantic skill catalog beats directory listing.
- **Knowledge-RAG MCP** (`search_knowledge`) is the fallback when text
  search misses and the topic is semantic, not keyword-shaped.

## Verification

Before finishing a task that created something, one line in the report:
"relevance scan: checked <layers>, nothing relevant existed / extended
<path>". This is what keeps the skill honest — a scan that leaves no
trace never happened.
