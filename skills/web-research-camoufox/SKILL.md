# Web research: Camoufox to the max

Source: `CAMOUFOX.md`. Web research — NOT decoration and NOT the last
step: first action for any task with choice. Internet = friend,
source of truth, help, teacher.

## Workflow (application order)

1. **Choose the evidence source.** If the question concerns existing project/workspace knowledge, use `db-first-search` with a verified target root and database. Use web research for external, current, or otherwise missing knowledge; database-first and web-first are complementary, not contradictory.
2. **Standard research.** `web_search("topic")` — 2-3 queries from DIFFERENT angles → `fetch_page` the best (primary source, not retelling) → second best in parallel → verify: fact in one — confirmation in another → `findings.py add` with conclusions.
3. **Depth — per task.** Reference (syntax, command): one pass, 2-3 sources. Decision/choice/design — DEEP research: 5-10 web_search from different angles IN PARALLEL (topic map) → select clusters → depth on 1-2 best from each. "Digging in" simple = token waste, "skimming" complex = solution from guesses.
4. **Research cycle (spiral, not circle).** RESEARCH → HYPOTHESIZE (if X, then Y, because Z) → EXPERIMENT (real action) → ANALYZE (what was confirmed/refuted) → LEARN (conclusions to research.db). Stuck/plateau → RETURN to RESEARCH for new knowledge (different angle, adjacent topic, primary source), don't hammer the same hypotheses.
5. **Evaluate sources with SIFT** (Michael Caulfield, WSU): **S**top (don't trust first impression) → **I**nvestigate source (who is the author) → **F**ind better coverage (independent coverage) → **T**race claims (to primary source). 2+ independent sources for key facts. Link next to the assertion.
6. **Learn from other developers.** Reference repos (README → tests → early commits → git log: most-edited files = core). One task in 2-3 different projects (difference in approaches = lesson). Real PRs (what gets rejected in review = how they think). Issues (why they chose this way). ADR/RFC/design docs (context → options → choice → rejected).
7. **Choose standard by measurement, not feeling.** How many real production projects use the approach (check source/docs, not retellings). Search for direct comparisons "X vs Y", "why we moved from X to Y". Authority: official docs > personal articles; freshness more important than age. Survivor bias: popular examples of terrible code — NOT the standard. Choice outcome = pattern + why it won + what was rejected (without the rejected, it's not a decision, it's a guess).
8. **After research — MANDATORY.** Conclusions to research.db (`findings.py add`, `--source` for report, `--related` for related). Deep research — report in `docs/research/<date>-<topic>.md`. If code changed — rebuild project database.

## Tools (8)

| Tool | What it does | When to use |
|------|-------------|-------------|
| `ping` | connectivity check | before long series |
| `web_search(query, pages=1)` | Current generic web-search surface; pagination support depends on the active tool schema | external research when the tool is available and arguments are verified |
| `read_url(url)` / verified page reader | Readable text extraction from a URL | documentation or page reading when the current tool surface supports it |
| `batch_fetch` | Batch page retrieval only when exposed by a verified browser/MCP implementation | bounded multi-source research; otherwise fetch individually |
| `browser_navigate` | text + first links | orient yourself |
| `browser_click` | click by selector/text | "next", tabs, buttons |
| `browser_type` | input in field | search forms |
| `extract_links` | collect links (filter) | download/source links |
